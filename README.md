# depviz — визуализатор графа зависимостей apk

## Общее описание

CLI-инструмент на Python 3 (только стандартная библиотека), который строит
граф зависимостей пакета Alpine Linux (формат `apk`). Менеджеры пакетов и
сторонние библиотеки для получения зависимостей не используются: индекс
`APKINDEX.tar.gz` скачивается и разбирается самостоятельно.

## Функции и настройки

### Параметры командной строки

| Опция | Описание |
|-------|----------|
| `-p`, `--package` | имя анализируемого пакета (обязательная) |
| `-r`, `--repo` | URL репозитория или путь к файлу тестового репозитория (обязательная) |
| `-m`, `--repo-mode` | `remote` (по умолчанию) — реальный URL, `test` — файл тестового репозитория |
| `-d`, `--max-depth` | максимальная глубина анализа, целое >= 0 (по умолчанию 3) |
| `-f`, `--filter` | не учитывать пакеты, в имени которых есть эта подстрока |

На первом этапе при запуске все параметры выводятся в формате
`ключ: значение`. Ошибки (неверное имя пакета, не-http(s) URL, отсутствующий
файл, неверный режим, отрицательная или нецелая глубина, пакет совпадает с
фильтром) выводятся как `error: ...` с кодом возврата 2.

### Сбор данных (этап 2)

Для `--repo-mode remote` указывается каталог репозитория, например
`https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64`; к нему
добавляется `APKINDEX.tar.gz`. Архив скачивается через `urllib`, из него
читается файл `APKINDEX` (записи разделены пустой строкой, строки вида
`K:значение`; `P` — имя пакета, `D` — зависимости, `p` — что пакет
предоставляет).

Правила разрешения зависимостей:

* ограничения версий отбрасываются (`zlib>=1.0` -> `zlib`);
* виртуальные имена (`so:libz.so.1`, `cmd:sh`, `pc:...`) заменяются
  пакетом, который их предоставляет (поле `p`);
* конфликты (`!pkg`), зависимости на самого себя и имена, которых нет в
  индексе, пропускаются.

На этом этапе выводятся прямые зависимости пакета. Ошибки загрузки и
неизвестный пакет дают `error: ...` и код возврата 1.

### Граф зависимостей и тестовый режим (этап 3)

Граф строится обходом в глубину **без рекурсии** (явный стек, см.
`graph.traverse`):

* глубина ограничена `--max-depth`; узел раскрывается повторно, только если
  найден более короткий путь до него, поэтому ограничение применяется к
  кратчайшему расстоянию от корня;
* пакеты, в имени которых есть подстрока `--filter`, не учитываются (ни как
  узлы, ни как рёбра);
* циклы (включая зависимость пакета от самого себя) не приводят к
  зацикливанию — ребро фиксируется один раз, повторный обход не делается.

**Тестовый режим** (`-m test`): вместо URL передаётся путь к файлу вида

```
# комментарий
A: B C
B: C
C:
```

Имена пакетов — заглавные латинские буквы. Пакет, упомянутый только как
зависимость, считается листом. Примеры лежат в каталоге `examples/`
(`chain`, `diamond`, `cycle`, `shortcut`, `prefixed`).

### Обратные зависимости (этап 4)

Опция `--reverse` выводит пакеты, которые зависят от заданного (прямо или
транзитивно). Используется тот же итеративный DFS, но по графу с
перевёрнутыми рёбрами (`graph.reverse_adjacency`), поэтому `--max-depth`,
`--filter` и обработка циклов работают так же. Рёбра печатаются в
исходном направлении «зависящий -> зависимость».

```
$ python -m depviz -m test -r examples/diamond.txt -p D --reverse
Reverse dependency graph of D (max depth 3):
  B -> D
  C -> D
  A -> B
  A -> C
Packages (4):
  D (depth 0)
  B (depth 1)
  C (depth 1)
  A (depth 2)
  C (depth 1)
```

### Визуализация (этап 5)

| Опция | Описание |
|-------|----------|
| `--dot FILE` | записать граф на языке Graphviz DOT в файл (`-` — в stdout, текстовый вывод при этом отключается) |
| `-o`, `--output IMAGE` | построить изображение (`png`, `svg`, `pdf`) программой Graphviz `dot` |
| `--show` | открыть изображение в просмотрщике (без `-o` создаётся временный png) |

Корневой пакет подсвечивается, рёбра всегда идут «зависящий -> зависимость»
(в режиме `--reverse` тоже). Для изображений нужен установленный Graphviz
(`apt install graphviz`, `brew install graphviz`); без него выводится
`error: Graphviz 'dot' is not installed`, а `--dot` работает всегда.

## Сборка проекта и запуск тестов

Сборка не требуется: нужен только Python 3.10+ (внешних зависимостей нет).

```
make test      # запуск unit-тестов (python -m unittest)
make lint      # проверка стиля: длина строк/функций, число аргументов, docstring
make demo      # демонстрация всех этапов (scripts/demo.sh)
```

Запуск без make: `PYTHONPATH=src python3 -m depviz --help`.

## Примеры использования

```
# параметры/ошибки (этап 1)
python -m depviz -p curl -r ftp://x                    # error: ... http(s) URL

# реальный репозиторий Alpine (этапы 2-3)
URL=https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64
python -m depviz -p curl -r $URL -d 2
python -m depviz -p curl -r $URL -d 3 -f lib           # без пакетов с "lib"
python -m depviz -p musl -r $URL --reverse -d 1        # кто зависит от musl

# тестовый репозиторий (этапы 3-4)
python -m depviz -m test -r examples/cycle.txt -p A -d 10
python -m depviz -m test -r examples/diamond.txt -p D --reverse

# визуализация (этап 5)
python -m depviz -m test -r examples/cycle.txt -p A -d 10 -o cycle.png --show
python -m depviz -p curl -r $URL --dot curl.dot -o curl.svg
```

Готовые DOT-файлы для трёх случаев лежат в `examples/dot/`:
`diamond-A.dot` (ромб), `cycle-A.dot` (цикл и самозависимость),
`diamond-D-reverse.dot` (обратные зависимости). Изображение:
`dot -Tpng examples/dot/cycle-A.dot -o cycle.png` (картинки в репозиторий
не коммитятся, см. `.gitignore`).

## Сравнение со штатным инструментом apk

Штатный аналог — `apk dot` (генерирует граф в формате Graphviz). Чтобы
сравнить результаты, на Alpine (контейнер `docker run -it alpine:3.20 sh`)
выполните для тех же пакетов:

```
apk dot curl > apk-curl.dot
python -m depviz -p curl -r $URL -d 10 --dot depviz-curl.dot
```

Ожидаемые причины расхождений (проверяйте по реальному выводу):

* `apk dot` работает через решатель зависимостей apk и учитывает
  установленные пакеты и выбранные репозитории, а `depviz` просто идёт по
  полю `D` одного индекса;
* виртуальные зависимости (`so:`, `cmd:`, `pc:`) `depviz` заменяет
  пакетом-поставщиком (первым найденным в индексе), `apk` может выбрать
  другого поставщика или показать их отдельными узлами;
* `depviz` отбрасывает ограничения версий, конфликты (`!pkg`) и имена,
  которых нет в индексе одного репозитория (например, пакеты из
  `community` при указании только `main`);
* `depviz` ограничивает глубину `--max-depth` и фильтрует по подстроке,
  у `apk dot` таких настроек нет.
